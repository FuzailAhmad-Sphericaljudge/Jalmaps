# Phase 03 — Internationalisation

- **Status:** Complete
- **Branch:** `phase/03-i18n`
- **Date:** 2026-10-01

## What was built

A complete internationalisation foundation with next-intl — locale-prefixed
routing, typed messages, formatters, language switching, pseudo-localisation,
and two CI gates that keep every locale in lockstep with English:

- **next-intl core** — `src/i18n/{config,routing,navigation,request,types}.ts`,
  Next 16 **proxy** (`src/proxy.ts`; middleware was renamed in Next 16) with the
  `NEXT_LOCALE` cookie chain, `/en` + `/hi` locale prefixes with
  `localePrefix: "always"`, `[locale]` route group (layout, page, not-found,
  catch-all), `AppHeader` with skip link, `LanguageSwitcher` (native
  `<select>`, native names, `router.replace` preserving the pathname), and the
  dev design-system gallery moved under `[locale]`.
- **Typed messages** — registry with per-locale loaders (`satisfies`, never a
  return-type annotation), `EnglishMessages` inferred into the `AppConfig`
  augmentation (must augment **`use-intl`**), so every `t("…")` key is
  compile-checked against the English tree.
- **Per-locale fonts** — `getFontClassName(locale)`: Inter for `en`; Inter +
  Noto Sans Devanagari for `hi`, with an `html[lang="hi"]` CSS stack reorder.
- **Formatters** — `src/lib/format/numbers.ts` (Indian digit grouping,
  compact lakh/crore, dates in `Asia/Kolkata`, relative time, percent, signed)
  and `depth.ts` (m/ft preference, float-safe `roundTo`). `hi-IN` formats with
  Latin digits by default — deliberate, asserted in tests.
- **Gallery translation** — the design-system gallery is fully key-driven in
  both locales (~150 keys in `gallery.json`).
- **ICU mini-parser** (`src/i18n/icu.ts`) — extracts arguments and
  plural/select options, recursing into nested choice bodies; powers the
  consistency gate.
- **Pseudo-localisation** (`src/i18n/pseudo.ts`) — accented, ~40%-expanded
  transform (`[…!!!]` brackets, combining U+0308) applied to English messages
  via `NEXT_PUBLIC_PSEUDO_LOCALE=1` or the `?pseudo=1` proxy cookie
  (`?pseudo=0` clears).
- **CI gate `pnpm check-i18n`** (`scripts/check-i18n.ts`) — per-namespace
  comparison of every locale against English: missing/extra keys, ICU argument
  mismatch, plural/select option drift; wired into `pnpm check` with
  fixture-tree unit tests.
- **ESLint `jalmaps/no-raw-jsx-text`** (`eslint-rules/no-raw-jsx-text.mjs`) —
  errors on literal JSX text in `src/**` (tests excluded; wordmark,
  `code`/`pre`/`option`, and `{"…"}` containers allowed). Dialog/Sheet close
  labels moved to `common.close` with a `closeLabel` prop for provider-less
  usage. RuleTester unit tests in `src/lint/`.
- **Playwright i18n e2e** (`e2e/i18n.spec.ts`) — default-locale redirect,
  unknown-locale fallback, language switching (home + nested routes),
  `NEXT_LOCALE` cookie persistence, pseudo brackets + overflow smoke.
  Existing specs migrated to `/en/...` URLs.
- **Docs** — `docs/i18n.md` (architecture + add-a-locale recipe),
  this phase note, `.env.example` pseudo flag, PROJECT_CONTEXT status.

## Decisions

- **Proxy, not middleware** — Next 16 renamed the convention; the file is
  `src/proxy.ts` with a default export and the same matcher style.
- **Augment `use-intl`, not `next-intl`** — next-intl's server types do not
  re-read a `next-intl` augmentation the same way; `use-intl`'s `AppConfig` is
  the one that counts.
- **`satisfies` in the registry** — annotating the loader return type would
  collapse JSON inference and turn every `t()` key into `never`.
- **Per-namespace comparison in the checker** — the first draft merged all
  English namespaces into one map and compared each locale namespace against
  the whole thing, reporting ~648 false "missing key" problems. Keys are now
  compared within their namespace only (shared key names like `title` across
  namespaces stay independent).
- **Latin digits for `hi-IN`** — `Intl.NumberFormat` defaults to Latin digits
  for Hindi in Node/browsers; Devanagari digits would require an explicit
  `u-nu-deva` extension. Tests assert Latin digits so a silent change is
  caught.
- **`closeLabel` prop on Dialog/Sheet** — keeps the primitives renderable in
  provider-less contexts (tests, storybook-style pages) while defaulting to
  the translated `common.close` in the app.
- **Vitest inlines `next-intl`/`use-intl`** — pnpm isolation breaks their
  `next/navigation` import otherwise; `next/font/google` and
  `next/navigation` are mocked in `vitest.setup.mts`.
- **Stale build cache gotcha** — a leftover `tsconfig.tsbuildinfo` masked real
  typecheck state with phantom message-type errors;
  `rm -f tsconfig.tsbuildinfo && rm -rf .next` resolves it.

## Verification

- `pnpm check` (lint incl. the new rule + typecheck + unit tests +
  `check-i18n`) passes — 27 test files, 172 tests.
- `pnpm build` succeeds; `[locale]` routes render on demand per request (the
  layout reads the theme cookie, which opts them out of static prerendering).
  `setRequestLocale`/`generateStaticParams` remain in place so the routes can
  go static if the cookie read moves client-side later.
- `pnpm test:e2e` passes — 10 tests across home, design-system a11y and the
  new i18n spec.
- Hindi copy is functional first-pass translation; native review is tracked
  for the launch checklist (see `docs/i18n.md`).
